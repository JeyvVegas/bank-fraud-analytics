# Проверка качества данных

## 1. Исходные данные

Исходный датасет содержит 6 362 620 транзакций и 11 столбцов.

Данные были предоставлены в формате CSV. При первоначальной работе через DBeaver поля CSV определялись как текстовые, поэтому данные импортировал в MySQL для полноценного SQL-анализа.

---

## 2. Проверка структуры данных

На этапе первичного анализа были проверены:

- количество строк;
- структура и типы данных;
- наличие пропусков;
- наличие дубликатов;
- распределение fraud-класса;
- значения `type`;
- значения `isFraud`;
- значения `isFlaggedFraud`.

Датасет не содержит критических проблем с пропусками и дубликатами и подходит для проведения fraud-анализа.

---

## 3. Проверка балансов

Была выполнена проверка соответствия балансов отправителя ожидаемым значениям после операции.

Для `CASH_IN` использовалась логика:

`newbalanceOrig = oldbalanceOrg + amount`

Для остальных типов операций:

`newbalanceOrig = oldbalanceOrg - amount`

При проверке учитывалась погрешность хранения денежных значений типа `DOUBLE`.

Анализ показал значительные расхождения в balance-полях для некоторых типов операций.

---

## 4. Ограничения balance-полей

Результаты проверки показали, что balance-поля нельзя использовать как абсолютный источник истины для оценки финансового состояния клиента.

Поэтому дальнейшие выводы о fraud не основывались исключительно на этих полях.

Это ограничение было учтено при построении аналитики.

---

## 5. Создание очищенной таблицы

После анализа исходного слоя `fraud_raw` была создана таблица `fraud_clean`.

Денежные поля были приведены к типу:

`DECIMAL(18,2)`

Это позволило избежать проблем с точностью денежных значений и использовать подготовленный слой данных для дальнейшей работы в Power BI.

---

## 6. Итог

Проверка качества данных позволила:

- выявить ограничения исходных balance-полей;
- учесть особенности хранения денежных значений;
- подготовить отдельный очищенный слой `fraud_clean`;
- не использовать потенциально ненадёжные поля как единственную основу для fraud-выводов.

После подготовки данных `fraud_clean` использовалась как основа для дальнейшего анализа и Power BI Dashboard.
